# Tabibako サブエージェント使い方ガイド

このディレクトリには Tabibako プロジェクト用のサブエージェント定義が置かれています。サブエージェントはメイン会話と独立したコンテキストで動くため、**コンテキスト汚染の防止** と **第三者視点の維持** が主な目的です。

---

## エージェント一覧

| エージェント | 色 | 用途 | 主な起動タイミング |
|---|---|---|---|
| `mock-consistency-checker` | 🟢 green | モック v6 と `index.html` の差分検証 | Sprint 完了時の整合性チェック |
| `code-reviewer` | 🟠 orange | 第三者視点のコードレビュー | Sprint 完了時、または大きめのリファクタ後 |
| `spec-qa` | 🔵 blue | 仕様書 3 ファイル + SPRINT_LOG を参照した Q&A | 仕様確認のたびにメイン会話で Read したくないとき |
| `translator` | 🟣 purple | 和訳/英訳・要約 | 突発的な翻訳依頼 |

カラーは UI 上でどのサブエージェントが起動中か視覚的に判別するためのもの。すべて `model: sonnet` で動作。重い判断が必要な場面では `opus` に切り替えてもよい。

---

## 起動方法

### 明示起動（推奨）

`@<エージェント名>` で名指しする。一番確実。

```
@mock-consistency-checker Sprint 1 完了時点のモック整合性を確認してください

@code-reviewer index.html を辛口でレビューしてください

@spec-qa 訪問都道府県の自動判定は誰がいつやる仕様？

@translator SPRINT_LOG.md を英訳して SPRINT_LOG.en.md に出力してください
```

### 暗黙起動

各 md ファイルの `description` フィールドにトリガー条件を書いてあるので、Claude Code が文脈から自動選択する場面もあります。確実性が必要なときは明示起動を使ってください。

## 使い分けのフロー

### Sprint 完了時のルーティン

```
1. 実装をひととおり書き終える
       ↓
2. @mock-consistency-checker と @code-reviewer を並列起動
   （独立タスクなのでメイン会話から同時に投げてよい）
       ↓
3. 指摘を取り込んで修正
       ↓
4. SPRINT_LOG.md を更新
       ↓
5. 動作確認（Chrome で index.html を開く）
```

並列起動する場合は **1 メッセージ内で複数の Agent 呼び出し** を投げると同時実行されます。

### 仕様確認

「マルチセレクトの値プールのキー名は？」「訪問都道府県は自動判定？手動？」のような問いは `spec-qa` に投げる。

メリット：
- メイン会話で 3 ファイル（`tabibako_spec.md` / `tabibako_claude_code_prompt.md` / `tabibako_mockup_v6.html`）を Read せずに済む
- 仕様未定義の項目を「未定義」と明示してくれる（推測で補わない）

### 翻訳

研修成果物として英語版を残す場合：

```
@translator 指示書/tabibako_spec.md を英訳して tabibako_spec.en.md に出力
@translator SPRINT_LOG.md を英訳して SPRINT_LOG.en.md に出力
```

外部ドキュメントの和訳要約：

```
@translator https://github.com/Leaflet/Leaflet.heat の README を和訳要約
```

## エージェントへのプロンプトの書き方

サブエージェントは **メイン会話の履歴を見ない**。指示は自己完結させること。

### 悪い例
```
@code-reviewer さっき書いた関数をレビューして
```
→ 「さっき書いた関数」が何か分からない。

### 良い例
```
@code-reviewer index.html の 280-330 行に追加した旅行登録モーダルの
イベントハンドラ周辺をレビューしてください。特に localStorage への
保存タイミングと、入力バリデーションの境界処理を重点的に。
```

具体的な範囲・観点・背景を 1 メッセージに込める。

---

## 並列起動の例

メイン会話から 1 メッセージ内に複数の Agent 呼び出しを書くと、独立タスクとして同時実行されます。Sprint 完了時の典型パターン：

```
以下を並列で実行してください：
- @mock-consistency-checker Sprint 2 完了時点のモック整合性
- @code-reviewer Sprint 2 で追加した旅行登録モーダル周辺のレビュー
```

返ってきた指摘をマージしてから修正に着手する流れが効率的です。

## 制約・注意

- **サブエージェントはこのプロジェクトのファイルを Read できる**が、それ以外の知識（過去の会話・他プロジェクト）は持ちません。プロンプトに必要な情報を入れること。
- **`code-reviewer` には「単一 HTML 構成への分割提案」「React/TS 移行提案」を出さないよう** 既に制約済み（CLAUDE.md の確定方針）。
- **`spec-qa` は実装コード（index.html）を根拠にしない**。仕様 ≠ 実装。実装が仕様から逸脱している可能性を前提に動きます。
- **`mock-consistency-checker` は SPRINT_LOG.md の意図的差異を確認してから判定する**。それでも判定不能な場合は「❓ 要確認」として残します。

---

## 定義の更新

各エージェントの振る舞いを変えたい場合は、対応する `.md` ファイルの本文を編集してください。`description` を変えると暗黙起動の選ばれやすさが変わります。
