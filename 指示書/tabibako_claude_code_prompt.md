# Tabibako — Claude Code 指示プロンプト

---

## このプロジェクトについて（背景）

これはAnthropicへの中途入社研修の自由課題として作成するWebアプリです。
研修の指示内容は以下の通りです：

> - Anthropic Skilljar の無料講座（Claude 101 / Claude Code 101 / Introduction to Claude Cowork / Claude Code in Action / Introduction to agent skills / Introduction to subagents / AI Capabilities and Limitations）を修了済み
> - 自分が作りたいサービスを設定し、企画書・仕様書を作成した上でClaude Codeを活用して実装すること
> - 数ショットで終わるような課題は避け、仕様をしっかり言語化して「AIにコードを書かせる」アプローチを意識すること

私はWebアプリ開発経験がなく、ウォーターフォール開発経験のみのエンジニアです。
今回はアジャイル的に「小さく動かしながら積み上げる」進め方で実装したいと考えています。

## アプリ概要

**アプリ名：Tabibako（旅箱）**

旅行・お出かけを「構造化されたデータ」として記録し、地図と写真で振り返るパーソナル旅行データベース。
記録が積み重なるほど、ヒートマップで自分の旅の傾向が浮かび上がる。

**差別化ポイント：**
- Google マップ マイマップ・Google Photos：旅行単位でのデータ構造化ができない
- Notion：地図・ヒートマップによる可視化ができない
- 本アプリの価値：旅行単位で構造化された記録DBに、地図可視化が組み合わさっている点

## 技術スタック（決定済み）

| 用途 | 採用技術 |
|------|----------|
| 地図表示 | Leaflet.js + OpenStreetMap（無料・ライセンス不要） |
| ヒートマップ | Leaflet.heat プラグイン |
| 住所検索 | Nominatim API（無料・APIキー不要） |
| データ保存 | ローカルストレージ（サーバー不要） |
| フロントエンド | HTML / CSS / JavaScript（単一ファイル構成を優先） |

**補足：** ReactやTypeScriptは使わず、まずは素のHTML+CSS+JSで動くものを作ることを優先してください。

## 画面レイアウト（UIモックを最優先で参照）

> ⚠️ 画面デザインは添付のUIモック画面を最優先で参照してください。
> 以下のテキスト仕様と齟齬がある場合はモックを正とします。

**3カラムレイアウト（トップバーなし・画面全体を使い切る）**

```
┌──────────────┬──────────────────────────┬──────────────┐
│  旅行一覧    │        地図              │  旅行詳細    │
│  （左 256px）│       （中央 可変）      │  （右 260px）│
│              │                          │              │
│ ・アプリ名   │ ・左上：ピン数表示       │ ・写真（矢印 │
│ ・ソートボタン│ ・右上：ヒートマップ btn │   切り替え） │
│ ・＋ボタン   │ ・右下：ズームコントロール│ ・詳細情報   │
│ ・絞り込み   │                          │ ・編集・削除 │
│   （3セクション）                        │   ボタン     │
│ ・旅行カード │                          │              │
│   一覧       │                          │              │
└──────────────┴──────────────────────────┴──────────────┘
```

**左パネル詳細：**
- ツールバー：「Tabibako」テキスト ＋ ソートボタン（↑↓アイコン）＋ ＋ボタン　を横並び
- ソートボタン押下でドロップダウン表示（日程：新しい順 / 古い順 / 旅行名：あいうえお順）
- 絞り込みセクションは「移動手段」「同行者」「タグ」の3セクションに独立分離
  - 各セクションで該当する値をタグとして表示し、クリックでオン/オフ切り替え
  - 移動手段：青系ハイライト / 同行者：緑系ハイライト / タグ：紫系ハイライト
- 旅行カードには「旅行名・日程・訪問都道府県・タグ」を表示
- 選択中のカードは青枠でハイライト

**中央パネル詳細：**
- Leaflet.js の地図を全面表示
- ヒートマップ切り替えボタン：地図右上にオーバーレイ（丸角ボタン）
- ピン数表示：地図左上にオーバーレイ
- ズームコントロール：地図右下

**右パネル詳細：**
- 上部：写真ビューア（高さ140px）。左右矢印ボタンで1枚ずつ切り替え。右下に「2/4」形式のカウンター表示。object-fit: contain で全体表示
- 詳細情報エリア：旅行名・日程・訪問地（都道府県）・移動手段・同行者・宿泊所・タグ・メモを表示
- 移動手段は青タグ、同行者は緑タグ、タグは紫タグとして表示
- 下部：編集ボタン・削除ボタン

## 旅行データ定義

```json
{
  "id": "uuid",
  "name": "旅行名（必須）",
  "startDate": "2024-09-14（必須）",
  "endDate": "2024-09-15（必須）",
  "places": [
    { "name": "訪問場所名", "lat": 35.0, "lng": 135.0 }
  ],
  "prefectures": ["滋賀県"],
  "accommodation": "宿泊所名（任意）",
  "transport": ["自転車", "電車"],
  "companions": ["一人"],
  "tags": ["ビワイチ", "達成"],
  "memo": "メモ（任意）",
  "photos": ["base64またはDataURL"]
}
```

**マルチセレクト型プロパティの設計：**
- transport / companions / tags はそれぞれ独立した値プールをlocalStorageに保存
- 値プールキー例：`tabibako_transport_pool` / `tabibako_companions_pool` / `tabibako_tags_pool`
- transport の初期値プール：["徒歩", "自転車", "車", "電車", "バス", "飛行機", "船"]
- 入力UI：既存値をタグ表示でクリック選択 ＋ テキスト入力で新規追加

### Sprint 1：骨格と地図表示（最初に動かすもの）

**目標：** ブラウザで開いたとき3カラムレイアウトが表示され、中央に地図が表示される状態

**タスク：**
1. `index.html` 1ファイルでアプリの骨格を作る（HTML + CSS + JS を1ファイルに）
2. 3カラムレイアウトをCSSで実装（左256px固定 / 中央可変 / 右260px固定）
3. Leaflet.js + OpenStreetMapを組み込んで地図を表示する
4. 左パネルに「Tabibako」テキスト・ソートボタン・＋ボタンのツールバーを仮置き
5. 右パネルに旅行詳細エリアを仮置き（中身は空でよい）

**完了条件：** ブラウザで開いたとき地図が表示され、ズーム・ドラッグ操作ができること

---

### Sprint 2：旅行データの登録

**目標：** ＋ボタンから旅行を1件登録してlocalStorageに保存できる

**タスク：**
1. 旅行登録フォームをモーダルまたはスライドパネルで実装
2. 旅行名・開始日・終了日の入力
3. 訪問場所の登録（住所テキスト入力 → Nominatim API で緯度経度取得 → 登録）
4. 地図クリックでも訪問場所を登録できるようにする
5. 登録データをlocalStorageに保存する
6. 保存後、左パネルの旅行一覧に旅行カードが表示されること

**完了条件：** 旅行を登録して再読み込みしてもデータが残り、一覧に表示されること

---

### Sprint 3：地図ピン表示と詳細パネル

**目標：** 旅行を選択したとき地図にピンが表示され、右パネルに詳細が表示される

**タスク：**
1. 旅行カードをクリックすると選択状態になる（青枠ハイライト）
2. 選択した旅行の訪問場所を地図上にピン表示する
3. ピンをクリックすると訪問場所名がポップアップ表示される
4. 右パネルに選択旅行の詳細情報を表示する（旅行名・日程・各プロパティ）

**完了条件：** 旅行選択→地図ピン表示→右パネル詳細表示が一連で動作すること

---

### Sprint 4：残りのプロパティ入力と写真

**目標：** 移動手段・同行者・タグ・宿泊所・メモ・写真を登録できる

**タスク：**
1. マルチセレクト型UIコンポーネントを実装（移動手段・同行者・タグ共通）
   - 既存値をタグ表示でクリック選択
   - テキスト入力で新規値を追加してプールに保存
2. 宿泊所・メモのテキスト入力
3. 写真のファイル選択・DataURLとしてlocalStorageに保存

5. 右パネルで移動手段・同行者・タグをカラータグとして表示（青・緑・紫）

**完了条件：** 全プロパティを入力して保存・表示できること

### Sprint 5：編集・削除・絞り込み・ソート

**目標：** データ管理と一覧操作が完成する

**タスク：**
1. 編集ボタンから登録済みデータを編集できる（登録フォームを再利用）
2. 削除ボタン → 確認ダイアログ → 削除
3. 左パネルの絞り込みセクション実装（移動手段・同行者・タグの3セクション独立）
4. ソートドロップダウン実装（日程新しい順・古い順・旅行名順）
5. 訪問都道府県の自動判定（緯度経度から都道府県名を逆引き）

**完了条件：** 登録・編集・削除・絞り込み・ソートがすべて動作すること

## Claude Code活用の指針

### サブエージェントの使い方
複数の独立したタスクが同時に発生した場合にサブエージェントへ分割してください。
向いているケースの例：
- 「マルチセレクトUIコンポーネント」と「都道府県判定ロジック」を並列で実装する
- 「写真のDataURL変換処理」と「localStorageの読み書きユーティリティ」を同時に作る

向いていないケースの例：
- 開発環境のセットアップ（順番に確認しながら進める対話作業のため、メイン会話で行う）
- エラーのデバッグ（文脈の共有が必要なため、メイン会話で行う）

### フックの活用
- ファイル保存時に自動でコードの構文チェックを走らせる
- スプリント完了時に `SPRINT_LOG.md` へ実装内容・決定事項・残課題を自動追記する

### コンテキスト管理（重要）

`/clear` はコンテキスト（会話履歴）を削除しますが、**ファイルは削除されません**。
ただし「どんな設計判断をしたか」「どんなエラーを解決したか」という文脈も失われるため、むやみに使うと危険です。

**推奨する運用：**

1. 各スプリント完了後に以下を指示する：
   ```
   このスプリントの実装内容・設計上の決定事項・残課題を SPRINT_LOG.md に追記してください。
   ```

2. 次のスプリントを始めるときは以下のように指示する：
   ```
   SPRINT_LOG.md を読んで現状を把握した上で、Sprint N を始めてください。
   ```

3. `/clear` は「会話が長くなりすぎてレスポンスが遅くなってきた」と感じたときだけ使う。
   その際は必ず事前に SPRINT_LOG.md を更新しておくこと。

### コンテキスト汚染の回避
- 試行錯誤中のコメントアウトや使われないコードは、スプリント完了時に削除してからログを書く
- 「とりあえず動く」コードと「整理されたコード」を混在させない
- 「前のスプリントで決めた設計」は SPRINT_LOG.md に書いておき、Claude Code が参照できるようにする

### スキルの活用
スプリントごとに以下のように指示してください：
```
SPRINT_LOG.md を読んで現状を確認した上で、Sprint N のタスクを実装してください。
完了したら動作確認のチェックリストと SPRINT_LOG.md の更新内容を出力してください。
```

## Step 0：開発環境のセットアップ（最初にやること）

> ⚠️ Sprint 1 の前に、以下の環境構築を完了してください。
> **わからないことがあれば Claude に質問しながら一緒に進めてください。**
> 環境構築はメイン会話（Claude.ai）で行い、Claude Code は環境が整ってから使い始めます。

### 確認済み環境

| 項目 | 内容 |
|------|------|
| OS | Windows 11 |
| ブラウザ | Google Chrome |
| Node.js | v24.15.0 |
| Claude Code | 2.1.140 |

環境構築は完了済みです。Sprint 1 から開始できます。

| ツール | 用途 | 確認コマンド |
|--------|------|------------|
| Node.js（v18以上） | Claude Code の実行環境 | `node -v` |
| npm | パッケージ管理 | `npm -v` |
| Claude Code | AIコーディングツール | `claude --version` |
| VS Code（推奨） | コードエディタ | — |
| Google Chrome | 動作確認ブラウザ | — |

### セットアップ手順

**1. Node.js のインストール確認**
```bash
node -v   # v18.0.0 以上であればOK
npm -v    # 同上
```
入っていない場合は https://nodejs.org/ からLTS版をインストール

**2. Claude Code のインストール**
```bash
npm install -g @anthropic-ai/claude-code
claude --version  # バージョンが表示されればOK
```

**3. プロジェクトフォルダの作成**
```bash
mkdir tabibako
cd tabibako
claude  # Claude Code を起動
```

**4. Claude Code の初期設定**
- 初回起動時に Anthropic アカウントでの認証を行う
- プロジェクトフォルダ内で起動することで、そのフォルダが作業ディレクトリになる

**5. 動作確認**
Claude Code 起動後、以下を入力して応答が返ってくればOK：
```
Hello! このプロジェクトでWebアプリを作ります。準備ができているか確認してください。
```

### つまずいたときは
- エラーメッセージをそのまま Claude Code に貼り付けて「このエラーを直して」と伝えてください
- Claude Code はファイルを直接確認・修正できるので、コピペ不要で解決できます
- OS（Windows / Mac）を伝えると回答が正確になります
- Node.js のインストール前など Claude Code 自体が使えない段階では、claude.ai で質問してください
