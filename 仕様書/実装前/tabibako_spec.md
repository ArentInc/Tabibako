# Tabibako（旅箱）仕様書

## 1. アプリ概要

### コンセプト
旅行・お出かけを「構造化されたデータ」として記録し、地図と写真で振り返るパーソナル旅行データベース。  
記録が積み重なるほど、ヒートマップで自分の旅の傾向が浮かび上がる。

### 既存サービスとの差別化
- Google マップ マイマップ・Google Photos：旅行単位でのデータ構造化ができない
- 経県値・たびちず：訪問場所の詳細情報（写真・メモ・同行者など）を持てない
- Notion：地図・ヒートマップによる可視化ができない

**本アプリの価値：旅行単位で構造化された記録データベースに、地図可視化が組み合わさっている点**

| 項目 | 内容 |

## 3. 画面構成

### 3.1 メイン画面（3カラムレイアウト・トップバーなし）

```
┌──────────────┬──────────────────────────┬──────────────┐
│  旅行一覧    │  [ヒートマップ切替]      │  旅行詳細    │
│  （左）      │         地図             │  （右）      │
│              │        （中央）          │              │
│ ・旅行リスト │ ・訪問場所ピン表示       │ ・写真矢印   │
│ ・ソート     │ ・地図クリックでピン追加 │   切り替え   │
│ ・絞り込み   │                          │ ・各プロパ   │
│              │                          │   ティ表示   │
└──────────────┴──────────────────────────┴──────────────┘
```

トップバーは持たない。ヒートマップ切り替えボタンは地図エリアの上部中央にオーバーレイ表示する。

### 3.2 左パネル：旅行一覧

- 登録済みの旅行が縦並びでリストアップされる
- 旅行カードには旅行名・日程・訪問都道府県を表示
- 旅行を選択すると中央地図にピンが表示され、右パネルに詳細が表示される
- 新規旅行追加ボタンを配置

**ソート・絞り込み機能**

| 項目 | 内容 |
|------|------|
| ソート | 日程（新しい順・古い順）、旅行名（あいうえお順） |
| 絞り込み：移動手段 | 移動手段の値プールから選択。選択した値を含む旅行のみ表示 |
| 絞り込み：同行者 | 同行者の値プールから選択。選択した値を含む旅行のみ表示 |
| 絞り込み：タグ | タグの値プールから選択。選択した値を含む旅行のみ表示 |
| 絞り込み：期間 | 年・月で絞り込み |
| 複合条件 | 移動手段・同行者・タグ・期間を組み合わせた絞り込みが可能 |

### 3.3 中央パネル：地図

- Leaflet.js + OpenStreetMap を使用（無料・ライセンス不要）
- 選択中の旅行の訪問場所をピンで表示
- 住所テキスト検索でピンを立てられる（Nominatim API 使用）
- 地図を直接クリックしてピンを立てられる

### 3.4 右パネル：旅行詳細

- 上部に写真を横スクロールで表示（Google マップの写真列イメージ）
- 各プロパティの内容を一覧表示
- 編集ボタンから旅行データの編集が可能

## 4. 旅行データ定義

### 4.1 プロパティ一覧

| プロパティ | 型 | 必須 | 備考 |
|------------|------|------|------|
| 旅行名 | テキスト | ✓ | 自由記述（例：「春の京都旅」） |
| 日程 | 日付範囲 | ✓ | 開始日〜終了日。日帰りは同日を指定 |
| 訪問場所 | 座標リスト | ✓ | 複数登録可。名称・緯度・経度を保持 |
| 訪問都道府県 | 都道府県リスト | 自動 | 訪問場所の座標から自動判定 |
| 宿泊所 | テキスト | - | 施設名など自由記述 |
| 移動手段 | マルチセレクト型 | - | 移動手段専用の値プールから選択 or 新規追加。初期値：徒歩・自転車・車・電車・バス・飛行機・船 |
| 同行者 | マルチセレクト型 | - | 同行者専用の値プールから選択 or 新規追加。人物名・グループ名で管理（例：田中さん・家族） |
| タグ | マルチセレクト型 | - | 移動手段・同行者とは独立した完全自由のラベル（例：青春18きっぷ・日帰り） |
| メモ | テキスト（長文） | - | 旅行全体の自由記述メモ欄 |
| 写真 | ファイルリスト | - | 複数添付可。旅行単位での添付（訪問場所との紐づけなし） |

> **設計メモ**：移動手段・同行者・タグは入力UIの方式は同じだが、それぞれ独立した値プールを持つ。移動手段の候補に同行者の値が混入することはない。Notionのマルチセレクトプロパティと同じ設計思想。

### 4.2 マルチセレクト型プロパティの共通仕様

移動手段・同行者・タグの3プロパティはすべて以下の仕様に従う。ただし値のプールはプロパティごとに独立して管理する。

| 項目 | 仕様 |
|------|------|
| 入力方式 | 既存値の一覧から選択 + テキスト入力で新規値を追加 |
| 複数選択 | 1つの旅行に複数の値を付与可能 |
| 値のスコープ | プロパティごとに独立（移動手段・同行者・タグで値プールは別管理） |
| 値の共有 | 一度追加した値は次回以降も同プロパティの候補として表示される |
| フィルタリング | 各プロパティ個別に絞り込み可能（移動手段・同行者・タグそれぞれ独立したフィルター） |
| 値の削除 | 将来対応（設定画面から不要な値を削除可能にする） |

**移動手段の初期値**：徒歩・自転車・車・電車・バス・飛行機・船

**同行者の値例**：田中さん・家族・一人・友人A など人物名・グループ名で自由に定義

**タグの値例**：青春18きっぷ・日帰り・ビワイチ・近代建築 など完全自由

### 4.3 訪問場所サブデータ

| 項目 | 型 | 備考 |
|------|------|------|
| 名称 | テキスト | 例：「清水寺」 |
| 緯度 | 数値 | 住所検索 or 地図クリックで取得 |
| 経度 | 数値 | 同上 |

## 6. ユーザーストーリー

### US-01 旅行の記録

**何がしたいか**  
旅行名・日程・訪問場所・移動手段・同行者・宿泊所・タグ・メモ・写真などの情報を、1件の旅行データとして登録したい。

**なぜ必要か**  
旅の記録を構造化して残しておくことで、あとから条件を指定して振り返ったり、地図と組み合わせて閲覧したりできるようにするため。

**期待される結果**
- 旅行名・日程・訪問場所を入力して保存できること
- 訪問場所を住所検索またはマップクリックで座標付きで登録できること
- 写真を複数枚添付できること
- 保存したデータが一覧に反映されること

---

### US-02 旅行の地図確認

**何がしたいか**  
一覧から旅行を選択したとき、その旅行の訪問場所が地図上にピンで表示されるのを確認したい。

**なぜ必要か**  
テキスト情報だけでなく地図で空間的に把握することで、「どのエリアを旅したか」が直感的にわかるようにするため。

**期待される結果**
- 旅行を選択すると訪問場所がピンで地図上に表示されること
- ピンをクリックすると訪問場所の名称が表示されること

---

### US-03 旅行の詳細閲覧

**何がしたいか**  
旅行を選択したとき、写真・日程・移動手段・同行者・メモなどの詳細情報を右パネルで一覧できるようにしたい。

**なぜ必要か**  
地図と詳細情報を同時に見ることで、「どこに行って、誰と行って、どんな旅だったか」を一画面で振り返れるようにするため。

**期待される結果**
- 旅行選択時に右パネルへ詳細情報が表示されること
- 写真が上部に表示され、矢印で1枚ずつ切り替えられること
- 全プロパティ（日程・移動手段・同行者・宿泊所・タグ・メモなど）が表示されること

---

### US-04 旅行の絞り込み

**何がしたいか**  
旅行一覧を移動手段・同行者・タグ・日程などの条件で絞り込んだり、並び替えたりしたい。

**なぜ必要か**  
記録が増えたときに「自転車旅だけ」「田中さんと行った旅だけ」のように特定の切り口で振り返れるようにするため。

**期待される結果**
- 移動手段・同行者・タグそれぞれ独立して絞り込みができること
- 複数条件を組み合わせて絞り込めること
- 日程の新しい順・古い順、旅行名のあいうえお順でソートできること

---

### US-05 旅行データの管理

**何がしたいか**  
登録済みの旅行データを編集・削除したい。また、移動手段・同行者・タグの選択肢を自分で追加・管理したい。

**なぜ必要か**  
入力ミスの修正や不要な記録の整理ができないと、データが信頼できなくなり使い続けられなくなるため。選択肢の管理は、自分の旅のスタイルに合わせてカスタマイズできるようにするため。

**期待される結果**
- 保存済みの旅行データをすべての項目について編集・上書き保存できること
- 旅行データを削除でき、削除前に確認ダイアログが表示されること
- 移動手段・同行者・タグそれぞれに新規値を追加できること
- 既存の値プールから選択して旅行に付与できること

---

### US-06 ヒートマップで傾向把握（オプション）

**何がしたいか**  
全旅行の訪問場所をヒートマップとして地図上に重ねて俯瞰したい。

**なぜ必要か**  
記録が積み重なるほど「自分がよく行くエリア」「まだ行っていないエリア」が視覚的に浮かび上がり、次の旅の計画に活かせるようにするため。

**期待される結果**
- ボタン1つでヒートマップモードに切り替えられること
- 全旅行の訪問場所の密度が色の濃淡で表示されること
- 移動手段・期間でフィルタリングしてヒートマップを更新できること

---

## 7. 技術スタック

| 用途 | 採用技術 | 理由 |
|------|----------|------|
| 地図表示 | Leaflet.js + OpenStreetMap | 無料・ライセンス不要・ドキュメント豊富 |
| ヒートマップ | Leaflet.heat プラグイン | Leaflet と統合済み・実装コスト低 |
| 住所検索 | Nominatim API | 無料・Google Maps API キー不要 |
| データ保存 | ローカルストレージ | サーバー不要・個人利用に十分 |
| フロントエンド | HTML / CSS / JavaScript（またはReact） | ブラウザのみで動作・デプロイ不要 |
